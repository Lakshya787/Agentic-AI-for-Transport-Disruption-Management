## 7. PYTHON PROJECT ARCHITECTURE (READ ONLY — for understanding)

### Controllers
- **B1 (rule-based):** Deterministic SOP. Reads structured JSON disruptions only. Blind to `reportedViaTextOnly=True` alerts.
- **B2 (single-LLM):** 1 LLM call → Routing Tool (Dijkstra) → Safety Guard
- **B3 (multi-agent):** Traffic Agent (LLM 1) → Fleet Agent (LLM 2) → Routing Tool (Dijkstra) → Coordinator (LLM 3) → Safety Guard

### Fleet (from scenarios.py)
- 6 vehicles: V0–V5 → webapp names V001–V006
- Positions: N0, N3, N4, N7, N12, N8 → webapp A0, A3, B0, B3, D0, C0
- Capacities: [4, 6, 4, 6, 4, 6]
- SoC ranges: L1–L3: 35–95%, L4–L5: 25–80%

### Safety Guard — 4 Deterministic Invariants
1. Topological: ∀(u,v) ∈ route: G_disrupted.has_edge(u,v)
2. SoC: vehicle.soc ≥ route_minutes × 1.0 × 1.15
3. Capacity: vehicle.capacity ≥ request.passengers
4. Concurrency: vehicle_id ∉ already_assigned_set

### Explainability (explainability.py) — 5 Dimensions
1. **Incident Reasoning:** Naive path vs disrupted, blocked segments, text advisory link
2. **Energy Proof:** Initial SoC, needed SoC (+15% buffer), projected post-trip SoC, verdict
3. **Triage Arbitration:** Priority tier (Emergency=3.0, Standard=1.0), allocation justification
4. **Detour Efficiency:** Chosen path time vs naive free-flow time, overhead %
5. **Safety Audit Certificate:** PASSED_UNCONDITIONAL or INTERCEPTED_AND_REPAIRED
